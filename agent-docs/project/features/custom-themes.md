# Custom browser themes

Customize offers **Native**, **Lune**, and **Custom**. Appearance stays independent and can follow macOS or be set to Light or Dark. Native uses AppKit colors. Lune keeps the authored Light and Dark palettes.

Customize defaults to 312 px and retains the saved width for a manually resized panel. Tinted settings cards sit inside a flush panel. **Customize Lune** heads the appearance card. Each section heading has 8 px above and 12 px below. On open and after a toolbar shortcut, the heading sits 4 px below the floating close button’s centerline in the 52 px top region. All settings scroll beneath the floating native close button, which hides as the closing motion begins. Panel text is nonselectable. Headings remain readable to assistive technology and can receive programmatic focus without a visible ring. Appearance and Theme have compact labels and matching segmented tracks. Each option uses the same font weight in selected and unselected states. Appearance uses Auto, Light, Dark order with SF Symbols. Native uses the Finder SF Symbol, Lune uses the monochrome paired-lune mark from Make default browser at favicon scale, and Custom uses the palette symbol. In Native, the pane and cards use two blends of the macOS window and neutral colors. Content reactive liquid glass stays with Appearance in a clickable settings row. Row highlights use 4 px side insets and a 5 px radius within 9 px cards. The **Customize New Tab** heading sits above its settings card. Change wallpaper appears before Show shortcuts. Change wallpaper and the toolbar reset button have centered icon-and-label groups and neutral outlines. The section only appears beside the built-in New Tab page. The Lune mark paints at 12 px inside its 15 px slot to match the surrounding symbols.

**Customize Toolbar** uses the same heading and card layout as **Customize New Tab** and appears immediately below it. The toolbar controls are available beside any tab. Toolbar customization commands open the main panel and scroll to the toolbar heading. The panel uses the thin macOS scrollbar with system visibility and colors. [Adoption checks](../builds/2026-11-27-customize-lune-panel.json)

Custom opens a 184 px hue and saturation wheel with a neutral outline. The wheel uses HSL lightness 70% in Light and 44% in Dark. Both appearances use the same selected point. Arrow keys adjust hue and saturation when the wheel has focus. Within 8 px of the center, the pointer snaps to zero saturation. Setup offers System, Lune, and Custom and opens the native panel when Custom is selected.

Chrome uses the latest wheel position at most every 100 ms during a drag and applies the final point on release. Each completed drag creates one undo entry. Cmd-Z undoes it. Cmd-Shift-Z and Cmd-Y redo it. Restore returns to the exact Custom palette that was active when the panel opened. Its visibility follows the last committed color throughout a drag. Closing the panel clears its history. Canceling a drag restores its starting palette.

The picker sends hue and saturation to ThemeService as an opaque sRGB seed encoded at HSL lightness 50%. This allows the active seed to use Chromium’s existing profile and theme-sync representation. Custom starts with a teal seed in a fresh profile. The macOS profile keeps its last Custom seed when switching to System or Lune. Existing preset, grayscale, and autogenerated themes appear under Custom and keep their loaded palette on upgrade. A wheel edit, or leaving an old palette and then reselecting Custom, applies the new generator. Managed themes keep their existing precedence.

The Custom Chroma variant scales the existing Tonal Spot primary, secondary, tertiary, neutral, and neutral-variant chromas by 1.5 times the seed saturation. The tertiary hue rotation, HCT gamut handling, Light and Dark tone selections, and semantic role assignments come from Chromium. The center produces neutral families. The existing error palette, native glass, and semantic browser role mappings still apply.
