# Search-engine suggestions in the address bar and Command-T

Status (November 10, 2026): implemented and owner accepted for [issue #23](https://github.com/leebyron/lune-browser/issues/23). The development lock adopts signed platform input `inputs/search-suggestions-1/macos` at `b33e3f250bb4b687cbe522ab3c514981f6c0f072` for future builds. Published releases retain their frozen inputs.

## Behavior

The floating address bar retains Chromium's autocomplete pipeline. Command-T now uses Chromium's `SearchProvider` for remote query suggestions and explicit website navigation suggestions, alongside its existing tabs, bookmarks, history and commands. Requests use the profile's selected default engine or the explicitly scoped engine. A scope without a suggestion template, including ordinary catalogue bangs and the tabs-only scope, never falls back to sending its query to the default engine. Custom engines can use the existing Suggestions URL field.

Suggestions use the existing `search.suggest_enabled` preference. New profiles taking the configurable onboarding path leave it off and can opt in on the search-engine page. Choosing Use defaults enables it before completing onboarding; the welcome page discloses that defaults include suggestions. Existing profiles retain their saved value. The onboarding bridge explicitly permits this one preference outside the existing Helium namespace; it does not expose arbitrary browser preferences. Search-engine disclosure and control remain separate from optional Helium services and browser-update consent.

Private windows, empty queries and disabled suggestions do not send Command-T suggestion requests. Chromium retains its checks for potentially private address-like input. An explicit engine scope intentionally sends its search terms to that engine. No current-page URL or title is supplied by the Command-T adapter. The adapter disables suggestion-image prefetch and geolocation priming; it does not add a second local history provider. Existing suggestion transport can use engine cookies, so opt-in is not a promise of anonymous requests.

Command-T keeps the direct typed URL or search action first before the nine-result cap, including after remote suggestions arrive. Recognized engine/tab scopes retain their explicit scoped action first, including when the entire scoped query is pasted. Direct and suggested searches use the same engine-name subtitle. The native viewport still displays five rows with scrolling. Query suggestions identify their engine; website suggestions are labeled Top hit and retain their explicit destination. Remote rows duplicate neither each other nor a typed/local destination. Asynchronous result updates preserve the selected activation identity rather than retaining a numeric index. Removing that item selects the first remaining result. Closing the palette, changing a query/scope/engine, or disabling suggestions cancels active timers/loaders and clears the previous remote results. The address editor also observes preference changes and restarts its autocomplete query immediately. Recognized keyword searches suppress Chromium's additional default-engine suggestion request, sending only the stripped search terms to the chosen engine.

The browser uses the existing engine definitions and response parsers. Suggestion endpoints can return empty results or reject requests. Full organic web-result previews, paid APIs, provider fallback and search-page scraping are outside this implementation. Engine-provided navigation suggestions supply top hits only where the selected engine returns them.
