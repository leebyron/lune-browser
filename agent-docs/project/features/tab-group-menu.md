# Native tab-group menu and inline naming

Implemented for [issue #33](https://github.com/leebyron/lune-browser/issues/33), requested November 12 and accepted November 13, 2026. Signed input `inputs/tab-group-menu-1/macos` (`60d037df61f275ec2edff170da907308a0fe3c54`) is selected by the development lock for future main builds. Published browser releases retain their frozen inputs.

## Behavior

Ordinary vertical tab groups on macOS use an AppKit context menu, reached through Chromium's native context-menu runner. The menu has no action icons and uses title-cased labels, with group pinning labeled simply **Pin** or **Unpin**. **Close Tabs in Group** replaces the former Close/Delete pair: it closes the member tabs and removes the saved group record. Normal History → Recently Closed recovery remains available.

Local group deletion runs without a group confirmation, including closing the final member with Cmd-W or a tab's close control, removing the final members and ungrouping. This policy belongs to the shared group-deletion controller, rather than only the context-menu callback. Shared-group collaboration flows retain their separate handling.

**Rename** opens an inline field in the header and selects the existing full stored title. Double-click does not enter editing. Creating a group through the browser's group command opens the same editor with an empty value and the placeholder **Name Group**. Enter commits, Escape cancels, and moving focus away commits. A window mouse-event monitor also commits after an outside click, including non-focusable sidebar space, while allowing the original click to reach its target. The monitor exists only while editing and is removed before widget teardown. Finishing a key-driven edit is deferred until event dispatch ends, so Enter does not also toggle collapse. While the inline editor is visible, the header does not handle collapse or reorder key shortcuts; Space belongs to the name field. The **Name Group** placeholder uses a dedicated theme-aware color at 30% opacity (8-bit alpha `0x4D`), while entered text and the caret keep their normal colors.

The editor fills the same row bounds as a member tab, with the same fixed horizontal text insets for every name, including emoji: `kTabHorizontalPadding + 2` on the left and `kTabHorizontalPadding` on the right. It measures no emoji prefix and does not reuse hidden-label geometry. Changing the insets explicitly refreshes the text renderer even when the row bounds stay the same. The complete stored title remains editable. Its focus ring draws inside the row bounds so the first pinned header remains unclipped at the scroll viewport edge. Renaming preserves collapse and local group-pin state. The owner accepted the final width, fixed insets and outside-click behavior on November 13.

Pin-state changes enable animated layout before the header invalidates it. This covers section-boundary moves without any model-index change, such as pinning the first regular group or unpinning into the first regular position. Startup and session-restore animation suppression remains in the shared controller.

Pin/unpin, new tab in group, moving to a new window, optional focus/home actions and ungrouping reuse their existing model operations. The native menu holds the sidebar's expansion and chrome reveal while tracking; inline editing retains the sidebar expansion and hover-card suppression until it ends. Horizontal groups and the temporary non-group focus-conversion editor retain their existing presentation.
