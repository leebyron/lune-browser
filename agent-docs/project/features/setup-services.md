# Setup Services and one-time password manager installation

Status: accepted November 14, 2026 and selected for future main builds through `inputs/setup-services-1/macos` at `956bc5a32fbdc7cdf89ee1ba5946683a6f69d71f`. Published 26.1114.1 remains unchanged. Privacy policy work remains deferred.

## Behavior

The sequence is Welcome, Search engine, Services, Import, Password manager, Customize. Services has no heading icon and introduces the section with “Control Lune’s connections beyond the websites you visit.” Automatic browser updates and search suggestions move here as the first two controls. They remain independent of Helium. The descriptions lead with the benefit and tersely name the recipient and request data, retaining the optional filter-list provider caveat; security/media component updates appear last and describe certificate protections and protected video playback.

A Block ads and trackers switch appears third, above the separator between local/browser controls and Helium services. Its description is “Enables the uBlock Origin extension with a pre-bundled filter list.” Services omits the custom-instance row. Its toggle controls retain rounded corners and background blur without an outline. Rows have no vertical gap between them; internal row padding remains, and the separator has 12px vertical margins. Fresh profiles keep the blocker uninstalled until Use Defaults or forward navigation from Services confirms the enabled switch. Toggling it, going Back, skipping Services, or completing setup with it off does not authorize a first installation. The pending choice and first-install authorization use separate preferences. Existing installations retain their enabled or disabled state on upgrade; confirmed changes use the normal extension registrar, preserving disable reasons and policy checks. The blocker can remain enabled with all Helium services off; its state does not determine the Helium master. The application still bundles its resources locally.

Setup omits the Helium master switch. The visible Helium choices determine its value, including setting it off when every applicable service is off. A profile with a previously disabled master displays its remembered service choices as off; choosing one service does not reactivate the others. Settings retains its existing master switch. Next confirms service consent and the suggested-search recommendation. Use Defaults and unchanged custom setup produce the same service preferences.

The password manager step and its progress dot remain available when extension services are off. Before any install, the page explains that choosing Install authorizes a one-time use of the extension proxy and does not enable future extension updates. Merely opening the page sends no extension-service request. Setup descriptions use balanced text wrapping. The disabled-extension warning block is centered on the page, with left-aligned text and a vertically centered warning triangle on its left.

The native onboarding handler restricts requests to the six offered password manager IDs and requires an explicit installation-only permission argument when ordinary service access is unavailable. The permission is carried by the selected installer through metadata and package downloads, including required modules. It is not a global preference override: unrelated extension installs, background extension updates, other Helium services, and saved consent/settings retain their existing gates. The normal native extension permission prompt and package verification remain in place.

Setup registers a standard browser leave warning while `completed_onboarding` is false. Completing setup or choosing Use Defaults clears that condition before navigation. The browser controls the wording and requires a prior user interaction before displaying a `beforeunload` prompt.

It covers the all-off master, each independent service, pending blocker selections, Back, forward dots, skipped Services, Use Defaults, disabled completion, restarts and legacy installed/disabled blockers. External hostname resolution is blocked, background networking remains enabled, and no password-manager account or vault is used.

Native cancellation downloads no package. A successful one-time installation survives restart with all Helium services still off. Missing permission, unlisted IDs and unrelated unapproved installs are rejected. Failed metadata requests preserve preferences. A subsequent extension-update attempt is rejected locally at the disabled-services URL and makes no fixture request; the test does not wait through the updater’s exponential retries.
