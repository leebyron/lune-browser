# Expanded Command-T commands

Owner accepted Preview 5 for [issue #17](https://github.com/leebyron/lune-browser/issues/17) on November 11, 2026. The feature is included in future main builds through signed platform input `inputs/command-bar-actions-1/macos` at `dece2e93ca27a8b6012cc20910ecfcf2a0e1ae6e`. It includes stateful tab/group and vertical-layout controls, conditional media actions and a relevant SF Symbol for every command. Published releases retain their frozen inputs.

## Discovery and interaction

Cmd-/ and Cmd-Shift-P open the same palette directly in commands-only mode with an empty input and the placeholder **Search commands**. Escape closes that palette immediately, including after a query is entered. Both shortcuts defer to the focused webpage or DevTools and open Lune command search only if the renderer leaves the event unhandled. The existing Cmd-T/Cmd-L behavior is retained.

Ordinary input continues to mix commands with navigation/search results. Typed URL/search priority, the nine-result mixed cap, engine/tab scopes and accepted bang behavior are preserved. Leading `/` outside an applied scope opens commands-only search; bare `/` lists the available catalogue in its curated order, using the existing five-row scrolling viewport without the mixed-list cap. `/restore`, `/undo close tab` and `/reopen` find Reopen Closed Tab; `/hard refresh` finds Reload Without Cache. Escape removes the command prefix and returns to mixed results; another Escape closes the palette. An applied engine scope treats `/` as search text. A leading `//` stays in ordinary navigation/search handling, and `>` has no special command behavior.

Recent and frequent invocations promote commands within the same text-match band; an exact match still beats a partial match. Bare `/` puts personal favorites first, falling back to curated order. Usage is stored in the local unsynced `helium.command_bar.command_usage` dictionary under stable registry keys, with saturated counts and last-use timestamps. Only accepted activations count, including opening a dialog even if it is later cancelled. Private windows read regular-profile ordering and never record usage. Queries and page URLs are not stored.

Unavailable commands are hidden. Availability and toggle labels refresh while open and are checked again on activation. A command selected explicitly by keyboard/pointer retains its identity across result updates; if it disappears, Enter has no selected action until a new query or selection. Each row uses the existing shared native result styling and its registry-provided SF Symbol. The right-hand text shows the first currently assigned keyboard shortcut when one exists, using BrowserShortcutService display text; otherwise it says Command. Customized and removed bindings are respected, and contextual Save/Copy/Inspect/sidebar wrapper shortcuts are shown only for the action they currently perform. The standard Zoom In shortcut is displayed as `⌘+`; custom and removed bindings are retained. Toggle symbols follow the chosen artwork for each action.

Tab and page commands target the invoking window's active pane/tab. Media commands use the shared playback target described below. Activation captures a weak page identity and invocation token, leaves the input event stack, rechecks the target and visible state, closes the palette synchronously, then dispatches. This lets Find, Print, DevTools and dialogs take focus after dismissal, and lets Close Tab destroy its window safely. A replaced/closed target, reopened palette, stale toggle or newly disabled command cannot redirect execution. Repeated Enter/clicks queue only one command.

The registry uses Chromium command support/enablement and dispatch for existing handlers. Pin Tab and Mute Site use focused adapters with Chromium context-menu eligibility, deliberately targeting the active pane even when unrelated tabs are selected. Muting is site-level and also affects other tabs from that site. Mute Site appears only when the active tab is currently/recently audible, using Chromium's two-second audio-indicator grace period. Unmute Site remains available while the site is muted, even after playback stops. The global media toolbar's visibility is not used to infer active-tab audio.

Media commands work across tabs in the invoking profile. A currently playing media session in the active tab takes priority; otherwise the target follows the global media toolbar’s local-tab item order, with playing sessions before paused ones. When no toolbar item is available, the active tab remains eligible for its own resumable media or picture-in-picture capability. Cast-only items and sessions from other profiles/private contexts cannot supply a tab target. The row’s secondary text names the target page. Mute Site / Unmute Site still apply to the active site.

All media actions use one selected session without borrowing a capability from a different tab. Play/Pause follows its reported playback state; Enter/Exit Picture in Picture follows its picture-in-picture state. Playback, track, seek, stop and ad actions require a controllable, non-inactive session and the corresponding supported action. Picture in Picture uses its own supported action, including video without controllable audio. Every action is revalidated on activation. The result stores the session’s stable request identity; session switches and closed targets cannot redirect an already selected or queued action, even when the replacement has the same title and symbol. Dispatch uses Chromium’s media-session methods, preserving registered site handlers; seek uses Chromium’s default five-second interval. Both seek directions match “skip”; directional aliases include “skip back” / “skip backward” and “skip ahead” / “skip forward”.

Sidebar and toolbar pinning use the existing native view/state controllers. Sidebar commands also accept aliases replacing “sidebar” with “tabs”, including “pin tabs”, “unpin tabs”, “move tabs to left” and “move tabs to right”. Narrow sidebar collapse is not offered.

Group Tab creates a group containing the active tab and opens its native editor; Remove Tab from Group removes only that tab. Both use `folder`, and “ungroup tab” matches the removal action only while grouped. The removal retains Chromium’s confirmation flow if it empties a group and captures weak window/page identities plus the expected group so a delayed confirmation cannot redirect to another group. New Tab Group uses `folder.badge.plus` and creates a new grouped tab using the native handler. Group commands are hidden when groups are unsupported. Group pickers, whole-window grouping, group closure and group navigation were deliberately excluded at the owner’s request.

The palette, trailing toolbar actions, action context menu and Customize Toolbar list share semantic symbol definitions: `wrench.and.screwdriver` for Developer Tools, `wrench.adjustable` for Customize Toolbar, `gauge` for Task Manager and `paintpalette` for Customize Lune. Sidebar pin controls use `sidebar.left` / `sidebar.right` according to placement. Toolbar pinning uses the macOS 13-compatible alias `rectangle.topthird.inset.filled` for the requested `inset.filled.topthird.rectangle` glyph. Both reload commands use `arrow.clockwise`; Skip Ad uses `arrow.right.to.line`.

## Complete catalogue

There are **53 command identities: 48 additions and five retained commands**. Toggle alternatives share one identity. Layout switching is not offered; Lune supports vertical layout. Sidebar positioning appears in vertical layout, and sidebar/toolbar pinning in Zen mode. Normal and private tabbed windows share the registry, subject to Chromium policy and page availability. App/DevTools-only windows do not expose this catalogue.

| Area | Added commands |
| --- | --- |
| Tabs and windows | Reopen Closed Tab; Duplicate Tab; Close Tab; New Window; New Private Window; Open File; Move Tab to New Window; New Split View |
| Browser UI | Show Bookmarks; Manage Extensions; Customize Lune; Customize Toolbar |
| Navigation | Go Back; Go Forward; Go Home; Reload Page; Stop Loading |
| Page actions | Find in Page; Find Next; Find Previous; Bookmark This Page; Print Page; Save Page; Zoom In; Zoom Out; Actual Size |
| Developer tools | Toggle Developer Tools; Open Console; Inspect Element; View Page Source; Task Manager; Reload Without Cache |
| Stateful tabs | Pin / Unpin Tab; Mute / Unmute Site; Group Tab / Remove Tab from Group; New Tab Group |
| Media | Play / Pause Media; Enter / Exit Picture in Picture; Previous Track; Next Track; Seek Backward; Seek Forward; Stop Playback; Skip Ad |
| Layout | Enter / Exit Fullscreen; Move Sidebar to Right / Left; Pin / Unpin Toolbar; Pin / Unpin Sidebar |

Retained commands: New Tab, Open Settings, Show History, Show Downloads and Copy Page URL. These now share registry metadata, native symbols and browser-command dispatch. New Tab uses the real New Tab command; Copy Page URL uses Chromium's standard URL-copy handler. New Split View adds a split pane using Chromium's existing split/new-tab flow. Print Page opens the existing print UI, including its PDF option. Customize Lune opens the existing appearance panel and uses its existing branded/localized title; Customize Toolbar opens that panel at its toolbar section.

Tab-group pickers, moving to an existing window, deeper DevTools frontend commands, DOM-derived page actions, translation/reading mode, media output-device pickers, call/camera controls and profile-wide cache deletion remain outside this implementation.

## Source and validation

Reusable platform patch: `patches/helium/ui/command-bar-actions.patch`, developed with quilt in `.work/search-suggestions/platform/build/src`, then refined in isolated `.work/command-actions/quilt-src` while another chat used the shared build tree. The patch is unmerged into `.work/command-actions/platform` on `topic/command-bar-actions` at signed commit `dece2e93`, composed with the accepted `inputs/services-update-controls-1/macos` input through merge `71681fab`. Core gitlink is unchanged. New palette labels are GRIT messages with English source text; translations are follow-up work under the existing string-localization issue.

Evidence lives under `.work/command-actions/`. Focused registry tests compile the production registry and dispatch with small window/policy/media-session doubles for both architectures; these test palette decisions rather than proving Chromium's independent handler behavior. They cover active-tab grouping and deferred confirmation, default/custom/removed Zoom In display, foreground-playing preference, background media in toolbar order, profile isolation and stable session identities, silent-site unmute, stale state/capability rejection, playback, picture-in-picture, track, seek, stop and ad dispatch. Existing bang and search-ranking/selection checks cover both architectures. The search-model harness now models deliberate selection explicitly and tests disappearing commands. Patch lint and exact zero-fuzz replay cover all 27 exported command files. The accepted services patch remains byte-for-byte unchanged; strict replay of eight active patches reproduces all 48 affected source files. This reuses the prepared baseline and does not claim a fresh full Chromium preparation. The native symbol audit resolves all 57 referenced symbols, including toggle alternatives; Apple's CoreGlyphs availability metadata dates every name to macOS 13 or earlier. macOS 13 runtime remains separate.

Both architecture builds pass in the shared prepared tree (`build-arm64.log`, `build-x86_64.log`); the final arm64 dependency-only rebuild preserves the earlier global-media build log as `build-arm64-global-media.log`. The isolated browsing/persistence, WebUI/settings and internal-icon smoke checks pass on both architectures (`smoke-arm64.json`, `smoke-x86_64.json`), with the final accepted component recorded in both reports. Intel runs under Rosetta on the Apple silicon host. Command/toolbar GN header checks and all 66 repository tests pass.

Earlier native previews verified page-first keyboard routing, the DevTools Command Menu, Settings `⌘,`, Escape dismissal, and focus/dispatch for Find, Print, Console and tab pinning. Preview 5 retains a separate test bundle ID/profile and normal internet access. Live Apple silicon inspection observed real internet audio playback; the owner accepted this final preview and requested development-lock inclusion. Further automated UI input overlapped owner testing, so the final cross-tab media dispatch coverage comes from the production-function fixtures and owner preview acceptance, rather than an exhaustive automated native-media run. These compiled fixtures check target priority and identity, capability loss, private/profile boundaries, playback/PiP/track/seek/stop/ad dispatch and native group confirmation routing.

Physical Intel, macOS 13, broad accessibility/IME and exhaustive managed-policy acceptance require separate validation. This records accepted development-input publication, not a new browser release.
